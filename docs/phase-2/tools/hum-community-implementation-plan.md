# Hum Community Implementation Plan
## Mobile-first Community Governance for Regenerant Catalunya Phase 2

**Tool:** Hum Community  
**Purpose:** Accessible community governance with low digital friction  
**Primary Network:** La Fundicio / Keras Buti  
**Status:** Ready for demo; adoption conditional on network validation  
**Last Updated:** 2026-02-23

---

## Overview

Hum Community is a mobile app for community governance that makes blockchain invisible to users. Members see euros, proposals, and simple thumbs up voting - no crypto knowledge required.

**Core Value Proposition:**
- **Accessibility:** Anyone with a smartphone can participate
- **Simplicity:** Familiar interface like social media
- **Inclusivity:** All network members can engage in governance
- **Transparency:** Decisions visible to whole community
- **No Barriers:** No Web3 knowledge or wallets required

**Why Hum Community for La Fundicio:**
- Territorial, presential approach values inclusion
- Skepticism of crypto complexity - Hum hides it
- Strong cooperative culture - participatory tools fit
- Mobile-first aligns with accessibility
- Lowers barriers to democratic participation

---

## Strategic Note: Flexibility & Validation

**Tool deployment is conditional on network validation:**

- **Kickoff call confirms network interest and capacity** - Validate interest before proceeding
- **Demo validates tool selection** - Test fit without forcing adoption
- **Implementation proceeds only with confirmed buy-in** - No forced implementation if networks aren't ready
- **Quality over quantity:** Focus on one solid case study vs. multiple incomplete attempts
- **Pivot options prepared:** If validation shows poor fit, we pivot rather than force implementation

**In-Person Workshop Conditional:**
- Initial demo is online for both networks
- In-person onboarding happens only if La Fundicio confirms adoption
- If in-person is not possible, we keep Hum as demo-only

## Implementation Direction

### Network Configuration
- **Partner Setup:** ReFi Barcelona partner portal already available
- **Demo Community:** Shared "Regenerant Catalunya" community for the demo
- **Community Structure:** Representative voting as default; open participation optional if desired
- **Governance Model:** Participatory budgeting with staged proposals
- **Treasury Handling:** Off-platform (Safe or bank transfer)

### Key Implementation Steps
1. Confirm demo date and participants (network-level leads)
2. Use shared demo community for a short, non-binding exercise
3. Run 10-15 minute hands-on voting with fake scenarios
4. Collect feedback on fit, friction, and governance alignment
5. Decide on adoption and in-person onboarding (La Fundicio)

### Support Structure
- **Demo support:** Light, synchronous guidance during the session
- **If adopted:** In-person onboarding + follow-up check-ins
- **Ongoing assistance:** Regular check-ins and troubleshooting

---

## Governance Model and Permissions

**Default (recommended): Representative voting**
- Representatives vote on behalf of the network (smaller, manageable group)
- Reduces coordination overhead and digital divide impact

**Optional (if network wants it): Open participation**
- Broader membership participates directly
- Requires stronger facilitation and onboarding

**Decision Gate:** Confirm which model the network wants after the demo

---

## Demo Design (Non-binding)

**Format:** Single combined online demo for both networks

**Scenario Structure (fake proposals):**
- 2-3 proposals with short descriptions and rough budgets in euros
- Example types: community event, equipment purchase, facilitation budget

**Agenda (45-60 minutes total):**
1. 10 min - Context and purpose (Hum is governance, not payments)
2. 15 min - Live walkthrough (ideas -> validation -> proposals)
3. 10-15 min - Hands-on voting on fake proposals
4. 10 min - Feedback and next steps

**Key Outputs:**
- Participation rate in demo
- Qualitative feedback on usability and legitimacy
- Decision on adoption or demo-only status

---

## Funding Integration (Safe + Bank Transfer)

Hum handles decision-making. Funds move off-platform.

**Option A: Safe Multisig**
- Use Hum decisions to trigger transfers from Safe
- Requires signers and standard multisig workflow

**Option B: Bank Transfer**
- Use Hum decisions to trigger bank transfers
- Fits existing accounting flows and lower crypto exposure

**Rule of thumb:**
- If network is comfortable with Safe, use Safe for execution
- If not, use bank transfer and keep Hum as governance layer only

## Success Metrics

- Demo participation rate (network-level leads + invited members)
- Number of proposals created and voted during demo
- Clarity of decision flow (survey feedback)
- Adoption decision (yes/no + conditions)

---

## Risks and Mitigations

- **Risk:** Digital divide limits participation
  - **Mitigation:** Representative voting default + buddy support
- **Risk:** Duplicate decision spaces create confusion
  - **Mitigation:** Position Hum as a test layer, not a replacement
- **Risk:** Perceived mismatch with real funds
  - **Mitigation:** Clear explanation: Hum decides, Safe/bank executes
