# Network-Specific Adaptations
## Miceli Social vs. La Fundición/Keras Buti - Regenerant Catalunya Phase 2

**Purpose:** Comprehensive documentation of how Regenerant Catalunya adapts to two very different network cultures  
**Key Insight:** One size does not fit all - same framework, different implementations  
**Application:** Guide for facilitating Phase 2 and template for other bioregional programs  
**Status:** Living document, updated throughout Phase 2

---

## Executive Summary

Regenerant Catalunya serves two cooperative networks in Catalunya with dramatically different approaches to technology, governance, and community organizing. Understanding and respecting these differences is critical to program success.

**Core Principle:**
> Tools and processes must adapt to network culture, not force networks to adapt to tools.

**What this means in practice:**
- Different language and framing for same tools
- Different support intensity and format
- Different tool recommendations
- Different success metrics
- Same respect and value for both approaches

## Adaptation Areas

### 1. Language & Framing

#### Miceli Social - Technical Language

**Use:**
- "Blockchain" and "on-chain" directly
- "Multi-signature wallet" or "multisig"
- "Smart contracts" and "transaction execution"
- "Web3 integration" and "DeFi protocols"
- "Governance mechanisms" and "threshold signatures"

**Frame tools as:**
- "Advanced infrastructure for network coordination"
- "Transparent and programmable governance"
- "Integration with broader Web3 ecosystem"
- "Experimentation opportunity"
- "Technical capacity building"

**Example messaging:**
> "Safe multisig gives you maximum transparency and control. All governance decisions recorded on-chain, with flexible threshold configurations. You can explore integration with other DeFi protocols and governance mechanisms."

---

#### La Fundición - Cooperative Language

**Avoid:**
- Heavy blockchain jargon
- Technical complexity
- "Crypto" or "cryptocurrency" emphasis
- Assumptions of technical knowledge

**Use:**
- "Digital cooperative tools"
- "Shared treasury" not "multisig wallet"
- "Approval process" not "threshold signatures"
- "Transparent financial records" not "on-chain transactions"
- "Community governance" not "DAO mechanics"

**Frame tools as:**
- "Supporting your existing cooperative values"
- "Making governance more accessible and transparent"
- "Digital version of what you already do well"
- "Serving your needs, not imposing technology"
- "Collective decision-making infrastructure"

**Example messaging:**
> "Home Community is like having a digital version of your cooperative assembly in your pocket. Vote on proposals with thumbs up or down, see how network resources are used, participate in budgeting - all without needing to understand blockchain technology."

## Replication Guidance for Other Bioregions

### Assessing Network Culture

**Before designing program, assess:**

**Technical Comfort:**
- High (tech-forward, experimental) → Can use complex tools
- Medium (willing but cautious) → Need moderate support
- Low (skeptical, traditional) → Must hide complexity

**Governance Style:**
- Distributed and networked → Safe multisig fits
- Centralized cooperative → Home Community fits
- Assembly-based → Participatory budgeting fits
- Informal/emergent → May not need tools yet

**Values Alignment:**
- Web3 positive → Emphasize blockchain benefits
- Web3 neutral → Frame as digital cooperative tools
- Web3 skeptical → Hide complexity completely, prove value first

**Support Availability:**
- Local team with capacity → Can serve complex and simple
- Remote support only → Stick to tech-comfortable networks
- Limited budget → Fewer networks but deeper support

---

### Adaptation Framework

**For each network, determine:**

1. **Language & Framing:**
   - Technical or cooperative terminology?
   - How to describe blockchain?
   - What values to emphasize?

2. **Tool Recommendation:**
   - Based on technical comfort
   - Based on governance culture
   - Based on support available

3. **Support Intensity:**
   - Light (tech-forward networks)
   - Medium (willing learners)
   - High (traditional cooperatives)
   - Very High (skeptical + critical infrastructure)

4. **Timeline:**
   - Fast adoption (weeks)
   - Medium adoption (months)
   - Slow adoption (longer, with option to opt-out)

5. **Success Metrics:**
   - What does success look like for THIS network?
   - Not one-size-fits-all metrics
   - Respect different goals

- Honor existing governance wisdom
- Use appropriate Spanish/Catalan terms

**Web3 Governance Language:**
- Understand blockchain technology
- Speak to ReFi ecosystem
- Reference protocols and DAOs
- Navigate technical implementation
- Connect to global public goods

**Bridge Building:**
- Translate between languages
- Find alignment points

- Build understanding across cultures

**Without these skills:**

- Won't build trust needed
- May impose rather than adapt

## Lessons for BioFi Ecosystem

### Key Takeaway

> **Bioregional finance infrastructure must be as diverse as bioregions themselves.**

**This means:**
- Multiple tool options (not single solution)
- Network cultural assessment (before design)
- Adaptive facilitation (not standardized)
- Variable support intensity (budget accordingly)
- Different success definitions (respect context)

**One-size-fits-all BioFi fails.**

**Culturally adapted, network-specific BioFi can succeed.**

---

### Recommendations for Tool Developers

**From Miceli Social experience:**
- Technical users want customization and control
- Integration with ecosystem valued
- Advanced features appreciated
- Documentation depth important
- Can handle complexity

**From La Fundición experience:**
- Non-technical users need radical simplicity
- Hide all blockchain complexity
- Cooperative framing essential
- In-app support and guidance critical
- Can't handle complexity (won't adopt)

**For tool developers:**
- Design for spectrum (not just one user type)
- Accessibility mode + advanced mode
- Cooperative UI/UX alongside crypto-native
- Support for various onboarding intensities
- Cultural customization options

---

### Recommendations for Funders

**From this experience:**

**Budget for differentiated support:**
- Don't assume same cost per network
- Tech-comfortable networks: 1x support budget
- Traditional cooperatives: 3-5x support budget
- Worth it for movement diversity

**Allow flexibility:**
- Networks may choose different tools
- Different timelines appropriate
- Some may not adopt Web3 (and that's OK)
- Measure outcomes, not tool adoption rates

**Value cultural bridging:**
- Fund teams with cooperative + Web3 fluency
- Support translation work (not just language, but cultural)
- Invest in bridge building long-term
- This enables Web3 to serve broader communities
