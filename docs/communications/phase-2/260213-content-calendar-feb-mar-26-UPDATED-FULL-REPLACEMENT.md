## 1) Why this update

This version replaces the previous high-frequency calendar with a **lean, decision-aligned communications plan**.

Latest team direction:
- keep comms simple and useful,
- prioritize execution and partner alignment,
- avoid overproduction,
- tie communications to actual phase milestones.

---

## 2) Operating principles

1. **Less, better:** publish fewer pieces with stronger clarity.
2. **Decision-first comms:** communications should reflect real implementation decisions.
3. **Notion as canonical artifact:** one structured Notion page for Phase 2 kickoff and follow-up.
4. **No forced channel activity:** publish when it adds context and value.
5. **Evidence over hype:** concrete updates, real constraints, practical learning.

---

### Primary
- **LinkedIn** (main channel)

### Secondary (optional)
- **Twitter/X** (mirror or short adaptation of milestone posts)
- **BlueSky** (optional mirror only if capacity exists)

### Optional
- **Newsletter** only if team capacity supports it without delaying core work

## 4) Core publishing cadence (3 milestone pieces)

## Milestone 1 — Article Publish + Framing Post
**Timing:** Immediate (as soon as article is ready and approved)

**Goal:** establish a clear reference point for external audiences.

**Content focus:**
- What was delivered in Phase 1
- Why Phase 2 matters
- What decisions now need to happen at network level

**Format:**
- LinkedIn primary post
- Optional Twitter/BlueSky mirror

---

## Milestone 2 — Mid-Phase 2 Update
**Timing:** middle of Phase 2 execution window

**Goal:** communicate concrete progress and implementation choices.

**Content focus:**
- Which pathway each network is using (Safe / Hum Community)
- Workshop progress and operational status
- Practical constraints (readiness, legal/accounting validation)

**Format:**
- LinkedIn update
- Optional short thread/mirror

---

## Milestone 3 — Final Post + Final Report Launch
**Timing:** end of Phase 2

**Goal:** close the loop with documented learnings and next steps.

**Content focus:**
- What worked
- What didn’t
- What is reusable for future rounds/regions
- Link to final report and key artifacts

**Format:**
- LinkedIn final post (primary)
- Optional mirrors

---

## 5) Phase 2 kickoff communications structure (for consistency)

Use this sequence in kickoff materials and related posts:

1. Context and objective
2. Decision required: **Safe vs Hum Community**
3. Roles and responsibilities by network
4. Risks + legal/accounting validation
5. Next steps and dates

**Important:** IDK/BioFi is positioned as **optional extension**, not a core operational requirement.

---

## 6) Critical operating rules

### Fund transfer gating rule
**Do not execute batch transfers until all required wallets/addresses are complete and validated.**

### Compliance clarity
All receiving/governance flows must be validated by each network’s accounting/legal context.

### Terminology standard
- Use **Hum Community** (not “Home Community”)
- Use **Safe** (sentence case in body text)

## 7) Asset plan (with fallback)

### Preferred assets
- Workshop/process photos
- Simple process diagram (Phase 1 → Phase 2)
- Minimal implementation visuals

### Fallback if photos are missing
Publish milestone update anyway using:
- concise text update,
- process screenshot/diagram,
- decision summary block.

No milestone should be blocked waiting for perfect visuals.
